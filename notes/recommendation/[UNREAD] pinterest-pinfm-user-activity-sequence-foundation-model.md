## 한 줄 요약

핀터레스트가 **2년치 사용자 활동 시퀀스로 사전학습한 20B 파라미터 트랜스포머**(대부분 임베딩 테이블)를 홈피드·연관 아이템(I2I) 랭킹 모델에 모듈로 붙여, **비용·지연을 거의 늘리지 않고** 서비스한 첫 산업용 사례. 성능보다 **"큰 모델을 기존 랭커 안에 어떻게 얹는가"** 가 글의 본체다.

> arXiv 2507.12704 (v3, 2025-07). 원문(arXiv HTML)을 읽고 정리. 아래 수치는 논문 표 그대로.

## 문제 배경

- 추천에서 사용자 활동 시퀀스는 가장 중요한 신호지만, 큰 시퀀스 모델은 **앱마다 따로 학습하면 감당이 안 된다**.
- 대안인 교사 모델 지식 증류는 **실험 사이클이 몇 달**로 느려진다(프로덕션 모델이 새 교사를 따라잡을 때까지 기다려야 함).
- 랭킹은 수백 ms 안에 **초당 수백만 아이템**을 스코어링해야 한다. 여기에 20B 모델을 얹는 게 난제.

## 큰 구도: 사전학습 → 앱별 파인튜닝

1. **사전학습**: 마지막 **2년** 활동 데이터, 시퀀스 최대 **16,000**, 백본은 GPT2(pre-LN). 비용 때문에 **고차원 피처를 쓰지 않는다** — 아이템 ID·행동 타입·지면 타입 임베딩만으로 학습(사전학습을 빠르게 하려는 선택).
2. **파인튜닝**: 사전학습한 트랜스포머와 임베딩 테이블을 각 앱의 랭킹 모델 안에 **모듈로 삽입**. 다른 기존 피처와 feature crossing으로 결합.
3. 핵심: 두 앱(홈피드·I2I)에 **비용 중립, 지연 소폭 증가**로 배포.

## 핵심 기술

**손실함수 3종** (LLM의 다음 토큰 예측을 추천에 맞게 개조)
- **L_ntl (Next Token Loss)**: 어휘가 수십억 개라 softmax 대신 **infoNCE**(대조 손실)로 계산. 긍정 행동이 있는 위치에만 적용해 연산을 크게 줄인다.
- **L_mtl (Multi Token Loss)**: 짧은 구간에서는 관심이 유지되므로 윈도우 안의 여러 미래 긍정 아이템을 함께 예측.
- **L_ftl (Future-Token Loss)**: 다운스트림 랭커는 지연 때문에 사전학습보다 짧은 시퀀스(L_d)를 쓴다. 그래서 **L_d 위치에서** 미래 윈도우를 예측 — LLM의 instruction fine-tuning과 비슷한 발상.

**후보 아이템과의 상호작용 (early fusion)**
- late fusion(시퀀스만 인코딩해 임베딩으로 넘김)은 캐시가 쉽지만 후보별 맥락화가 안 된다.
- **early fusion**: 후보 아이템을 시퀀스 끝에 붙여 넣는다. 성능이 더 좋아 채택. 여기에 후보 GraphSAGE 임베딩을 합산하고 앞에 learnable token을 붙인 **PinFM-GraphSAGE-LT**가 최고 조합.
- 사전학습 지식이 덮어써지지 않게 **사전학습 모듈 lr을 랭킹 모델의 1/10**로 두고, 랭킹 loss + 예측 정렬용 MSE loss를 함께 건다.

**효율 ① DCAT (Deduplicated Cross-Attention Transformer)**
- 관찰: **사용자 시퀀스는 후보 수보다 훨씬 적다**(서빙 1:1000, 학습 1:10).
- 시퀀스 쪽 transformer는 요청당 **한 번만** 돌리고 레이어별 **KV 캐시**를 저장 → 후보들은 cross-attention으로 그 캐시를 재사용. 배치 내 중복 시퀀스도 제거(dedup)해 계산.
- FlashAttention 기반 self-attention 대비 **서빙 처리량 600%↑, 학습 200%↑**. 추가로 시퀀스 길이를 256으로 고정하고 회전 마스크를 써서 **25% 더** 개선.

**효율 ② 임베딩 테이블 int4 양자화**
- 8개 서브 테이블(각 8천만 행 × 32차원)을 이어 붙여 256차원 임베딩 → **임베딩 테이블만 20B 파라미터**.
- 학습 후 **PTQ**: int4에서 벡터가 512bit → 160bit, 테이블 크기 **31.25%**로 축소, CPU 호스트 비용도 비례해 감소.
- 온라인 2주 A/B에서 **통계적으로 중립**(성능 손해 없음), 임베딩 IO 감소로 추론 API 지연 **7% 감소**.

**콜드스타트 3종**
- 후보 ID **무작위화 10%**(CIR): 콜드 아이템 ID가 학습 때 본 적 없는 값이라는 상황을 흉내.
- **아이템 나이 기반 dropout**(IDD): 7일 미만 후보는 p=0.7, 7~28일은 p=0.5로 모듈 출력을 dropout → ID 임베딩에 덜 의존하게.
- **GSLT**: 후보 GraphSAGE 임베딩 + learnable token.

## 성과

**오프라인 (HF Save HIT@3 상대 향상, 홈피드/연관 아이템)**

- **PinFM-base**: HF +2.91% · I2I +1.76%
- **PinFM-GraphSAGE**: HF +3.08% · I2I +1.92%
- **PinFM-GraphSAGE-LT**: HF **+3.76%** · I2I **+1.92%**
- **PinFM-lite-mean (시퀀스만)**: HF +1.87% · I2I +1.53%

**콜드스타트 (HF Save HIT@3, 28일·7일 이내 신선 아이템)**

- **PinFM-cs-none**: HF 전체 +3.36% · HF 28d **-4.40%** · HF 7d **-23.98%**
- **+ CIR**: HF 전체 +3.43% · HF 28d +1.25% · HF 7d -4.38%
- **+ CIR·IDD**: HF 전체 +3.49% · HF 28d +10.71% · HF 7d +8.16%
- **+ CIR·IDD·GSLT**: HF 전체 **+3.76%** · HF 28d **+17.72%** · HF 7d **+12.01%**

- 그냥 붙이면 신선 아이템에서 오히려 **나빠진다**(-4.40%). 콜드스타트 기법을 쌓아 +17.72%까지 회복한 게 이 논문의 실질적 기여.
- 원문 초록의 "신선 아이템 참여 20% 증가"는 **이 표의 상대 HIT@3 개선**(두 PinFM 변형 간 차이)을 가리킨다. 온라인에서 측정된 신선 세이브 향상은 아래 표의 **+5.70%**다.

**온라인 A/B (95% 신뢰수준에서 유의)**

- **Sitewide Saves**: HF 랭킹 **+1.20%** · I2I 랭킹 **+0.72%**
- **Surface Saves**: HF 랭킹 **+2.60%** · I2I 랭킹 **+2.09%**
- **Fresh Saves**: HF 랭킹 **+5.70%** · I2I 랭킹 -0.82%

- 기존 베이스라인도 시퀀스 트랜스포머를 쓰지만, 파라미터 수는 PinFM의 **0.2% 미만**.
- HF는 콜드스타트 기법을 적용(적용 전 약 -5% → 적용 후 약 +10%), I2I는 신선 세이브 하락이 허용 범위라 **미적용**.
- 두 지면 모두 **피드 다양성**(최근 노출·참여하지 않은 주제의 아이템 참여 수)이 증가.
- **실서비스**: 홈피드·I2I 랭킹에 배포, **5억 명 이상 사용자**에게 적용.

**그 밖의 ablation** (읽을 때 유용한 것만)
- **파인튜닝 없이** 붙이면(freeze) Save 향상이 +0.10%로 사라지고 Hide는 나빠진다 → LLM과 달리 **파인튜닝이 필수**.
- 임베딩 어휘 20M → 160M에서 Save +1.98% — 어휘 확장이 꾸준히 도움.
- 사전학습 반복은 약 **3 epoch**에서 비용·성능 균형. ID 기반 모델에서 흔한 1 epoch 과적합이 나타나지 않았다.
